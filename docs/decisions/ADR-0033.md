# ADR-0033: Single domain, no CORS

**Status:** Proposed
**Date:** 2026-08-02

## Context

The admin dashboard and the API are separate containers (ADR-0032) and could be exposed in two ways: as separate subdomains (`app.example.com` and `api.example.com`), or as one origin with path-based routing.

The choice looks cosmetic and is not. It determines the cookie configuration for authentication (ADR-0020), and therefore the security posture of every session.

With separate subdomains, cookies must be set with `Domain=.example.com` to be sent to the API, and — because the request is cross-origin — `SameSite=None`, which requires `Secure`. `SameSite=None` disables the browser's built-in CSRF protection, so CSRF tokens become mandatory. A CORS policy must also be maintained, including preflight handling and credentialed-request configuration.

With one origin, none of that exists: cookies are `SameSite=Lax` and host-scoped, there is no CORS, and no preflight.

## Decision

We will serve everything from **one domain**, with Caddy routing by path:

```
example.com/api/*   →  api container
example.com/*       →  admin container
```

- Cookies are **host-only** (no `Domain` attribute), `httpOnly`, `Secure`, `SameSite=Lax`.
- **CORS is not configured at all**, because there are no cross-origin requests.
- Caddy terminates TLS and manages certificates automatically.
- Future surfaces follow the same principle: the customer portal is a path or a separate domain with its **own** cookie scope, never a shared parent-domain cookie.
- The **partner API is the deliberate exception** — it is machine-to-machine, uses bearer credentials rather than cookies (ADR-0020), and may live on its own hostname without any of the above concerns.

## Consequences

**Positive**
- `SameSite=Lax` provides meaningful CSRF protection by default; the highest-risk cookie configuration is avoided entirely.
- No CORS configuration means no CORS misconfiguration — a common and easily overlooked source of vulnerabilities.
- No preflight requests, so slightly lower latency on mutations.
- Local development matches production: one origin, one reverse proxy.

**Negative / trade-offs**
- The API and admin app are coupled at the routing layer; splitting them onto separate hosts later requires revisiting cookie strategy and introducing CORS.
- A path prefix (`/api`) is reserved and cannot be used by an admin route.
- Caddy becomes a single point of failure for both surfaces. Acceptable on a single-VM deployment where the box is already the single point of failure.
- Independent scaling of the two containers behind one proxy is possible but less natural than with separate hostnames.

## Rejected alternatives

| Alternative | Why rejected |
|---|---|
| **Separate subdomains with a parent-domain cookie** | Forces `Domain=.example.com` + `SameSite=None` + `Secure`, which disables default CSRF protection and mandates CSRF tokens. Strictly worse security for no functional gain at this scale. |
| **Separate subdomains with bearer tokens in `localStorage`** | Exposes tokens to XSS. `httpOnly` cookies are the safer default for a browser-based admin surface. |
| **Separate domains entirely** | Same cookie and CORS problems, plus a second certificate and DNS configuration. |
| **API mounted inside the frontend framework's server** | Rejected in ADR-0004 for architectural reasons; this decision does not reopen it. The objection is framework-independent, and under ADR-0050 the frontend has no server to mount an API inside. |

## Enforcement

- **Caddyfile in version control** under `infra/docker/`; routing is reviewed as code, not configured on the server.
- **Startup assertion**: the API refuses to boot in production if a CORS middleware is registered with a non-empty origin list — a positive check that the no-CORS decision has not silently eroded.
- **Cookie assertion test**: an integration test asserts `Set-Cookie` carries `HttpOnly`, `Secure`, `SameSite=Lax`, and **no** `Domain` attribute.
- **Smoke test**: the post-deploy check authenticates through the proxy and calls an API path, so a routing regression fails the deployment (ADR-0037).
- **Security scan**: the CI security step flags `Access-Control-Allow-Origin: *` in any response.
