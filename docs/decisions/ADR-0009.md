# ADR-0009: Testing strategy

**Status:** Accepted
**Date:** 2026-08-02
**Accepted:** 2026-08-08 — ratified as wave W2 (architecture shape).

**Note — a passing test run is not a typecheck.** The suites run under `tsx`, which strips types rather than checking them, so a file with a type error executes happily and reports green. This bit the identity PR: 27 assertions passed locally while `tsc` rejected an invalid cast, and CI caught it. `typecheck` and `test` are therefore separate CI stages and neither substitutes for the other. The same shape as the rest of this branch's false greens — a check that reports success without having examined the thing it claims to check.
**Added beyond the supplied decision set** — see Enforcement for why. Retrofitting a test strategy after features exist is expensive, and several other ADRs name test suites as their enforcement mechanism, so those suites need a defined home.

## Context

Several decisions in this set are enforced by tests rather than by lint or database constraints: the permission model (ADR-0021), state machine transitions (ADR-0029), business number concurrency (ADR-0025), outbox durability (ADR-0026), and the conflict register's characterization tests (ADR-0003). Without a defined test taxonomy, those enforcement claims have no address.

Separately, the ability to test domain logic **with no database** is the observable proof that ADR-0006's purity rule holds. If a domain test needs a container, the boundary has already leaked.

The predecessor's test posture is not fully known, but its defect register shows invariants enforced on one code path and skipped on another (C12), which is the signature of behaviour verified by manual testing rather than by a suite.

## Decision

We will maintain four test layers with distinct guarantees and distinct execution costs:

| Layer | Scope | Infrastructure | Runs |
|---|---|---|---|
| **Domain unit** | Entities, value objects, state machines, policies | **None.** No DB, no container, no mocks beyond plain fakes | Every commit, milliseconds |
| **Use-case** | Application services against in-memory fake repositories implementing the port | None | Every commit |
| **Integration** | Repositories, adapters, migrations, outbox, RLS | Real PostgreSQL in a CI service container | Every PR |
| **Suite-level** | Role matrix, state machine legality, contract conformance | Real PostgreSQL | Every PR |

Named suites that other ADRs depend on:
- **Role-matrix suite** — generated from the mined role matrix; asserts allow/deny for every (role × endpoint × scope) triple, including IDOR probes with a foreign `organization_id` and a foreign owner.
- **State-machine suite** — for every aggregate, asserts every legal transition succeeds, every illegal transition throws (including backwards out of terminal states), and every reason-requiring transition rejects a null reason.
- **Characterization suite** — `c<NN>-*.spec.ts`, one per conflict-register item, tagged with its C-number.

We will not pursue a coverage percentage target. We will pursue named guarantees.

## Consequences

**Positive**
- Domain tests run in milliseconds with no setup, which keeps them actually run.
- The role-matrix and state-machine suites turn ADR-0021 and ADR-0029 from intentions into gates.
- C-number-tagged tests make it verifiable that a known defect has not been re-encoded.

**Negative / trade-offs**
- In-memory fake repositories must be maintained alongside real ones; they drift if the port changes and only one implementation is updated. Mitigated by making both implement the same TypeScript interface, so drift is a compile error.
- Integration tests need a Postgres service container, making PR runs slower than unit-only.
- Generating the role-matrix suite from a data file means a malformed matrix silently under-tests. The suite asserts a minimum triple count as a guard.

## Rejected alternatives

| Alternative | Why rejected |
|---|---|
| **Coverage percentage targets** | Rewards testing trivial code and is satisfied by tests that assert nothing meaningful. Named guarantees are auditable; a percentage is not. |
| **Integration tests only** | Slow feedback, and they would not prove the domain layer is framework-free — which is the specific property ADR-0006 needs demonstrated. |
| **Mocking the ORM in unit tests** | Tests would assert against mock behaviour rather than real SQL semantics, and would not catch the constraint violations that ADR-0014 relies on. |
| **Testcontainers per test file** | Container-per-file startup cost is disproportionate on a small CI runner; one shared service container with per-test transactional rollback is sufficient. |

## Enforcement

- **CI**: unit + use-case tests on every push; integration, role-matrix, and state-machine suites blocking on every PR (ADR-0037).
- **Purity guard**: a lint rule forbids importing the DB test harness from any path matching `**/domain/**`. A domain test that needs a database fails lint, not just review.
- **C-number coverage script**: CI cross-references every C-number marked "prevented" in `docs/mined/*.md` against the existence of a matching `c<NN>-*.spec.ts`; a missing test fails the build.
- **Fake/real parity**: both repository implementations satisfy the same interface, so a port change that updates only one is a TypeScript error.
