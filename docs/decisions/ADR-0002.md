# ADR-0002: Freeze the prototype at `apps/prototype`

**Status:** Accepted
**Date:** 2026-08-02
**Accepted:** 2026-08-08 — ratified as wave W1a (substrate). Amended at ratification: the replacement app is `apps/web`, not `apps/admin`, for consistency with ADR-0050 and ADR-0032.

## Context

The current `engipro-manager` code is a Vite SPA using HashRouter, Tailwind from a CDN `<script>`, React imported from esm.sh via an import map, all state in a single React context over mock data in `constants.ts`, and no tests, backend, or persistence.

Its **behaviour** is nonetheless valuable. It encodes workflows that have been clicked through and validated: client status lifecycle, phone/email dedupe guard, the RFQ approval chain, the 100%-payment-schedule gate, and quotation versioning. That is an executable specification, and it is worth more than a written one because it has been exercised.

Its **types** are the problem. `Client` inlines `interactions[]`, `documents[]`, and `statusHistory[]`. That is a screen projection, not an aggregate, and it is the exact violation of Vernon's rule that aggregates reference one another by identity rather than by object reference. Evolving that shape in place would make it the API response, then the database model, then the aggregate boundary — arriving at the predecessor's coupling problem from the opposite direction.

## Decision

We will `git mv` the current prototype to `apps/prototype` and **freeze it**:

- It remains runnable and demoable to stakeholders.
- It is **excluded from the dependency graph**: no path aliases, no imports in either direction, its own minimal tsconfig.
- Feature development on it stops.
- It serves two purposes only: stakeholder demo, and acceptance criteria for rebuilt flows.
- It is **deleted in a single PR** once `apps/web` surpasses it flow-for-flow.

We will not refactor it into the production web app.

## Consequences

**Positive**
- Stakeholders keep a working demo throughout the rebuild; nothing is lost if the rebuild runs long.
- `apps/web` is built once, correctly, rather than migrated one component at a time while also staying functional.
- The validated flows remain observable, which is stronger acceptance criteria than a document.

**Negative / trade-offs**
- Two UIs exist simultaneously for a period, which can confuse newcomers. Mitigated by the `README` banner in `apps/prototype` and its Status here.
- Bug fixes to the prototype are not made; if a demo reveals a flaw, it is recorded in `docs/mined/` rather than patched.

## Rejected alternatives

| Alternative | Why rejected |
|---|---|
| **Incrementally refactor the prototype into production** | Each step must keep the app working *and* move it toward a different architecture — you pay for both. The type inversion above means the refactor touches every file, which is not cheaper than rebuilding. |
| **Delete the prototype now** | Discards validated workflow behaviour and the stakeholder demo before the replacement exists. |
| **Keep it and wire it to the real API** | Would make a mock-data SPA a production client of the real contracts, entrenching its UI-shaped types in the API's response models. |

## Enforcement

- **Agent hook**: `PreToolUse` matcher on `Write|Edit` runs `tools/block-prototype-writes.sh`, which exits non-zero for any path under `apps/prototype/`. Hard block, not an instruction (ADR-0038).
- **dependency-cruiser**: the `no-app-to-app` rule forbids any import between `apps/*`, which covers both directions for `apps/prototype`.
- **CI**: `apps/prototype` is excluded from the lint, typecheck, and test matrices; it gets a build check only, so its absence of tests cannot fail the pipeline.
- **tsconfig**: no path alias maps to `apps/prototype`, so an accidental import fails to resolve at compile time.
