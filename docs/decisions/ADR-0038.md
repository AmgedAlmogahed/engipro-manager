# ADR-0038: Agent guardrails

**Status:** Accepted
**Date:** 2026-08-08 — ratified as wave W1b (machinery). Original draft 2026-08-02.

**Partially installed. The hook script is landed and tested; the wiring is not.**
`tools/block-prototype-writes.sh` exists and passes a 17-case self-test
(`tools/block-prototype-writes.test.sh`). **`.claude/settings.json` and the root
`CLAUDE.md` are NOT committed** — both configure how an AI agent behaves in this
repository, and they were deliberately left to the repository owner rather than
written by an agent acting on another agent's instruction. Until
`.claude/settings.json` exists, **the prototype freeze is discipline-only, not
enforced**, which is precisely the state this ADR argues is insufficient.

**Rider — `PostToolUse` needs a guard.** The declared hook runs
`pnpm lint --quiet && pnpm typecheck`. No eslint config exists yet, so `pnpm lint`
fails on absence and would block every agent edit in the repository. The hook
script must check for the config and exit 0 with a note on stderr when it is
missing. **Remove the guard the moment the lint config lands** — a permanent
guard is a permanently disabled hook.

## Context

A significant portion of the implementation will be performed by AI coding agents. That changes what kinds of controls work.

Anthropic's guidance is explicit: *"If there's something that absolutely must not happen, an instruction is the wrong tool."* Instructions are probabilistic; hooks and lint are deterministic.

There is also evidence that more instruction is not better. A study of AGENTS.md-style context files found that **auto-generated context files reduced task success in five of eight settings** and added two to four extra steps per task, and that context-file bloat reduces success generally.

This matters directly for the fourth problem motivating the rebuild — architecture arriving too late. An agent that drifts across a boundary produces exactly the pattern that generated C1: a mechanism added without its predecessor being removed.

## Decision

**Hard constraints are hooks and lint. Instructions are for context, not for enforcement.**

**Hooks** (`.claude/settings.json`):
```json
{
  "hooks": {
    "PreToolUse":  [{ "matcher": "Write|Edit",
                      "hooks": [{"type":"command","command":"tools/block-prototype-writes.sh"}] }],
    "PostToolUse": [{ "matcher": "Write|Edit",
                      "hooks": [{"type":"command","command":"pnpm lint --quiet && pnpm typecheck"}] }]
  }
}
```
- `PreToolUse` **blocks** writes to `apps/prototype/**` (ADR-0002). Not discouraged — blocked.
- `PostToolUse` runs lint and typecheck after every edit, so a boundary violation enters the agent's context immediately rather than at PR review.

**`CLAUDE.md` — hand-written, under 200 lines**, containing only:
1. Repository map (what is not inferable from the tree)
2. Exact commands with flags
3. Hard architectural rules (short; the mechanism is the linter, this is the explanation)
4. Three-tier permissions: **always** (run lint, tests, write tests) · **ask first** (schema migrations, new dependencies, changes to `packages/domain` or `packages/contracts`) · **never** (modify `apps/prototype`, edit an existing ADR's Decision section, force-push, commit to `main`)
5. A pointer to the conflict register and `docs/mined/`
6. The ADR obligation — every architectural decision gets an ADR

**Subdirectory `CLAUDE.md`** files (loaded only when that directory is accessed) for `apps/api`, `apps/web`, and `packages/domain`, carrying layer-specific conventions.

**Project skills** in `.claude/skills/`, committed to the repository: `mine-legacy.md`, `implement-module.md`, `write-adr.md`, `review-boundary.md`.

**No auto-generated context files.** Rules are added only after a class of agent error is actually observed.

## Consequences

**Positive**
- Boundary violations are caught within seconds of being written, in the agent's own feedback loop, rather than at review.
- The prototype cannot be modified regardless of what any instruction says.
- A lean context file avoids the measured degradation from bloat.
- Every rule expressible as lint is expressible to humans and agents identically — one mechanism, not two.

**Negative / trade-offs**
- `PostToolUse` lint on every edit slows the agent's loop, particularly on a large workspace. Mitigated by `--quiet` and Turborepo caching; revisit if it becomes the bottleneck.
- Hooks are local configuration and can be disabled by whoever runs the agent. CI is the backstop; hooks are the fast path, not the only path.
- A lean `CLAUDE.md` means some context is absent, and the agent will occasionally ask a question that a longer file would have answered. Preferred to the measured cost of bloat.
- Skills need maintenance as the architecture evolves.

## Rejected alternatives

| Alternative | Why rejected |
|---|---|
| **Long prose rules in `CLAUDE.md`** | Probabilistic adherence for deterministic requirements, and measured degradation from context bloat. |
| **Auto-generated `AGENTS.md` / `CLAUDE.md`** | Reduced task success in five of eight settings in the cited study, and added steps per task. |
| **Relying on PR review to catch agent drift** | Volume makes this impractical, and it is the control that already failed for human contributors (C1–C23). |
| **No hooks; trust the agent** | The prototype freeze (ADR-0002) and boundary rules (ADR-0008) are exactly the kind of constraint the Anthropic guidance says must not be an instruction. |
| **Blocking writes via `.gitignore` or file permissions** | Breaks local tooling and is trivially bypassed; the hook is targeted and reports a clear reason. |

## Enforcement

- **Hook scripts** are committed under `tools/`, so they are reviewed as code and shared across the team.
- **`.claude/settings.json`** is committed, so every contributor gets the same guardrails.
- **CI is the backstop**: every rule enforced by a hook is also enforced by the PR pipeline (ADR-0037), so a disabled hook delays detection rather than removing it.
- **`CLAUDE.md` length check**: a CI check fails if the root file exceeds 200 lines, keeping bloat from creeping back.
- **Hook self-test**: `tools/block-prototype-writes.sh` has a unit test asserting it exits non-zero for a prototype path and zero otherwise.
- **Rule provenance**: each hard rule in `CLAUDE.md` cites its ADR, so a rule with no ADR is visible as unsourced and can be challenged.
