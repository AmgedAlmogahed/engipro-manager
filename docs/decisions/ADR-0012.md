# ADR-0012: PostgreSQL as the only datastore

**Status:** Accepted
**Date:** 2026-08-02
**Accepted:** 2026-08-08 — ratified as wave W3 (data foundation).

## Context

The system runs on a single OCI Ampere ARM VM with roughly 6 GB of RAM. Every additional stateful service consumes memory that the application, the database, and the operating system need. Redis alone would take 256–512 MB.

The workload is an internal ERP: low volume, high complexity, transaction-heavy, with reporting that benefits from window functions, CTEs, and JSON operations.

## Decision

We will use **PostgreSQL 16 or later as the only datastore**, self-hosted in Docker initially, portable to managed PostgreSQL later.

PostgreSQL will additionally serve roles that are commonly given to separate infrastructure:
- **Job queue** — graphile-worker (ADR-0027), not Redis.
- **Event outbox** — a table (ADR-0026), not a message broker.
- **Full-text search** — `pg_trgm` / `tsvector`, not Elasticsearch.
- **Scheduling** — graphile-worker cron, not a separate scheduler.

We will use only standard PostgreSQL features and widely available extensions (`pgcrypto`, `pg_trgm`). No host-proprietary surface.

## Consequences

**Positive**
- One backup, one restore procedure, one connection pool, one thing to monitor, one thing to secure.
- Job scheduling and event dispatch are **transactional with business data** — a job enqueued in the same transaction as the state change cannot be orphaned. That is a correctness property Redis cannot offer.
- Portability across Docker → managed PostgreSQL → any cloud is `pg_dump` plus a connection string change.
- Memory budget stays within the 6 GB envelope (ADR-0032).

**Negative / trade-offs**
- PostgreSQL becomes a single point of failure for the application, the queue, and events simultaneously. Mitigated by ADR-0031's backup and restore regime, which is the compensating control.
- Job throughput ceiling is roughly 100–200 jobs/second versus Redis-backed alternatives at ~2,000. Irrelevant at ERP volumes; recorded here as the threshold at which this decision should be revisited.
- Heavy reporting queries and OLTP share one instance until a read replica exists (ADR-0030 defers that).
- Autovacuum health becomes operationally important, particularly for the outbox table (ADR-0026 addresses this by deleting rather than marking rows).

## Rejected alternatives

| Alternative | Why rejected |
|---|---|
| **PostgreSQL + Redis** | 256–512 MB of a 6 GB box for throughput that will not be approached, and it removes the transactional guarantee between business writes and enqueued work. Revisit if Redis arrives for another reason (session store, rate limiting). |
| **PostgreSQL + a message broker (Kafka/NATS/RabbitMQ)** | Operationally disproportionate at this scale; the outbox already gives durable events. Revisit at cross-service extraction. |
| **MySQL / MariaDB** | Weaker support for the specific features this design relies on: schemas as namespaces, partial indexes, `SKIP LOCKED` ergonomics, `numeric` semantics, RLS. |
| **A document database** | The domain is highly relational — clients, quotes, sections, line items, milestones, projects, phases — with invariants that benefit from constraints. |
| **Managed PostgreSQL now** | Cost with no current benefit; the ops burden at this scale is a nightly backup and a monthly restore drill. Revisit at Phase 4. |

## Enforcement

- **`docker-compose.*.yml`** pins the PostgreSQL image and version; no other stateful service is defined, so adding one is a visible, reviewable diff.
- **Migration lint** rejects DDL using non-standard or host-proprietary extensions.
- **Portability check**: a scheduled CI job restores the latest backup into a plain `postgres:16` container and runs the integration suite. If the system cannot run on vanilla PostgreSQL, this fails (this doubles as the ADR-0031 restore drill).
- **Dependency review**: adding a client library for another datastore requires an ADR; a CI check flags new dependencies matching a datastore denylist (`redis`, `ioredis`, `mongodb`, `@elastic/*`).
